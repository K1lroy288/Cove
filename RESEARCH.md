# Cove — Research & Development Plan

## 1. Исследование мессенджеров

### 1.1 Ключевые UX-паттерны (Telegram, Discord, WhatsApp, Signal)

#### Структура интерфейса
- **Двухпанельный лейаут** (десктоп): список чатов слева, окно чата справа. Стандарт для всех крупных мессенджеров.
- **Нижняя навигация** (мобайл): максимум 4-5 иконок, чаты на первом месте.
- **Поиск над списком чатов**, а не на отдельной вкладке (Telegram, WhatsApp) — пользователь остаётся в контексте.
- **Аватар + имя + превью последнего сообщения + время** в каждой строке списка — информационная плотность без перегруза.

#### Чат-пузыри (message bubbles)
- Сообщения отправителя — справа (цветные), получателя — слева (нейтральные).
- Скруглённые углы у пузырей: обычно 18–20px, «хвостик» только у крайних пузырей в группе.
- **Группировка сообщений**: несколько сообщений подряд от одного человека визуально объединяются, аватар показывается только у первого.
- Время внутри или под пузырём, галочки доставки/прочтения.

#### Реакции (Telegram, Discord, iMessage)
- Появляются при long press на сообщение.
- Emoji-панель: 6–8 быстрых реакций + кнопка "ещё".
- Реакции отображаются под пузырём с счётчиком.
- Анимация при добавлении реакции — обязательна.

#### Треды и ответы
- **Swipe на сообщение вправо** — быстрый ответ (Telegram, WhatsApp).
- Ответ-цитата: небольшой блок с именем и превью над полем ввода.
- **Треды** (Discord Threads, Telegram Topics): параллельные ветки обсуждения, вложенные в канал.
- Кнопка "Jump to message" при нажатии на цитату.

#### Закреплённые сообщения
- Плашка вверху чата с превью, тап — переход к сообщению.
- Несколько закреплённых — индикатор количества, свайп между ними.

#### Статусы и онлайн
- Зелёная точка = онлайн, серая = оффлайн, время последнего визита.
- **Typing indicator** (три точки) — появляется, когда собеседник печатает.
- **Delivery status**: отправлено (1 галочка) → доставлено (2 галочки) → прочитано (2 синие галочки).

#### Поле ввода
- Автоматически расширяется при многострочном тексте (до 5–6 строк).
- Кнопка отправки появляется только когда есть текст; в остальное время — кнопка голосового сообщения.
- Иконки: вложения, эмодзи, голос.

### 1.2 Паттерны голосовых чатов (Discord, Clubhouse, Mumble)

#### Архитектура голосовых комнат

**Discord (Voice Channels):**
- Голосовые каналы всегда видны в сайдбаре и **постоянны** — можно войти и выйти в любой момент.
- Участники видны прямо в списке каналов с аватарами.
- **Speaking indicator**: пульсирующий зелёный ободок вокруг аватара говорящего.
- Статусы: говорит / замьючен / наушники отключены (deafened) / камера включена / стримит.
- **Текстовый чат внутри голосового канала** — параллельный, не мешает голосу.
- Мини-панель внизу экрана: остаётся видна при навигации по другим разделам (persistent call bar).

**Clubhouse (Audio Rooms):**
- Комнаты эфемерны — существуют пока есть участники.
- Роли: **Speaker** (может говорить), **Listener** (слушает), **Moderator** (управляет).
- Кнопка "Raise Hand" для слушателей — запрос слова.
- Аватары спикеров крупнее, в верхней части комнаты.
- Кнопка выхода снизу: "Leave Quietly" — не прерывает других.

#### Ключевые UX-паттерны голосовых чатов
- **Push-to-talk** vs **Voice Activity Detection** — пользователь выбирает.
- **Noise cancellation** UI: кнопка с визуальным индикатором активности.
- **Echo/feedback prevention** — обязательно отключать микрофон при выходе.
- **Connection quality indicator** (хорошее/среднее/плохое соединение) — иконка рядом с именем.
- **Мини-панель активного звонка** (как у Discord) — позволяет переходить в другие части приложения не прерывая звонок.
- Список участников делится на: **Говорит**, **Замьючен**, **Подключается**.

#### Технические паттерны голоса
- **WebRTC** — стандарт для браузерных/мобильных голосовых чатов.
- **P2P (Mesh)**: до 4–6 участников, без сервера-посредника для медиа.
- **SFU (Selective Forwarding Unit)**: 6+ участников — каждый участник отправляет поток на сервер, сервер пересылает нужные потоки каждому. Livekit, Mediasoup, Janus.
- **Сигнализация через WebSocket**: обмен SDP offer/answer и ICE candidates.
- **TURN-сервер**: обязателен для надёжной работы за NAT/firewall.
- **Opus codec**: стандарт для голоса в WebRTC — низкая задержка, хорошее качество.

## 2. Технические паттерны (применимо к Cove)

### 2.1 Реал-тайм архитектура (Go + WebSocket)

**Стандартный подход (Gin + Gorilla WebSocket):**
```
Client (Flutter) ←→ WebSocket ←→ Go Hub ←→ PostgreSQL
                                     ↓
                               Broadcast goroutines
```

**Hub-паттерн** (центральный диспетчер сообщений):
```go
type Hub struct {
    clients    map[*Client]bool
    broadcast  chan []byte
    register   chan *Client
    unregister chan *Client
}
```
- Каждый клиент — отдельная горутина чтения + запись через канал.
- Hub получает сообщения и рассылает всем нужным клиентам.
- `sync.Map` или mutex для потокобезопасного доступа к списку клиентов.

**Аутентификация WebSocket:**
- JWT передаётся в query-параметре при upgrade (`?token=...`) или в первом сообщении после подключения.
- После валидации токена — привязка соединения к userId.

**Типы сообщений (JSON envelope):**
```json
{
  "type": "message" | "typing" | "read" | "presence" | "reaction",
  "payload": { ... }
}
```

**Reconnect с exponential backoff** на клиенте:
- 1s → 2s → 4s → 8s → max 30s.

### 2.2 Паттерны хранения сообщений

**Схема БД для чата:**
```sql
messages (
  id, chat_id, sender_id, content, type,
  created_at, edited_at, deleted_at,
  reply_to_id  -- для треков/ответов
)
reactions (
  message_id, user_id, emoji, created_at
)
message_read_status (
  message_id, user_id, read_at
)
```

**Пагинация**: cursor-based (по `id` или `created_at`), не offset — стабильна при добавлении новых сообщений.

### 2.3 Flutter-специфичные паттерны

- **WebSocket через `web_socket_channel`** пакет.
- **Stream + StreamBuilder** для отображения входящих сообщений.
- **Riverpod или BLoC** для state management чата.
- **Оптимистичное UI**: сообщение добавляется в список сразу, статус обновляется при подтверждении от сервера.
- **ListView.builder с reverse: true** для списка сообщений (новые снизу, но рендеринг идёт от конца).

## 6. Что отличает Cove от других

На основе ресёрча, уникальное позиционирование Cove:

1. **Голос как первый класс** — не дополнение к тексту, а равноправная фича (в отличие от WhatsApp/Telegram, где голос вторичен)
2. **Постоянные голосовые комнаты** в стиле Discord — не звонки, а пространства, в которые можно зайти/выйти
3. **Приватность по умолчанию** — только друзья, нет публичных серверов
4. **Голосовые реакции** — короткие аудио-сниппеты вместо emoji (уникальная фича, упомянутая в дизайне)
5. **Минималистичный UI** — меньше элементов, чем Discord, больше функций, чем WhatsApp
